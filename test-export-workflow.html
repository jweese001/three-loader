🔧 Code Export Workflow Testing

Test Scenario 1: Basic Code Export

1.
Select Code Export Option

In the export modal, click "Export Code" option on the left

2.
Configure Export Options
  • Choose viewport size (800x600 recommended for testing)
  • Select whether to include detailed comments
  • Enable/disable CDN vs local Three.js imports
3.
Generate and Download Code

Click "Generate Code" and verify the JavaScript file downloads

4.
Verify Generated Code

Open the downloaded .js file and verify:

  • Proper Three.js imports (CDN or ES6 modules)
  • Complete scene setup with renderer, camera, controls
  • All objects, materials, and lighting recreated
  • Animation loops and interactions preserved
  • Comments and documentation included if selected

Code Export Verification Checklist:

  • Scene geometry matches original viewport
  • Materials and textures properly referenced
  • Lighting configuration preserved
  • Animation state and parameters included
  • Camera position and controls configured
  • Code is valid JavaScript and executable
  • Asset paths correctly formatted
  • Error handling implemented

📦 Standalone Project Export Testing

Test Scenario 2: Complete Project Export

1.
Select Standalone Project Option

In the export modal, click "Standalone Project" option on the right

2.
Configure Project Settings
  • Enter project name (e.g., "MyThreeJSScene")
  • Enable "Include Assets" to bundle textures and models
  • Choose CDN or local Three.js distribution
  • Select viewport dimensions for final output
3.
Generate Project

Click "Export Project" and monitor the progress indicators

Note: Project export uses the File System Access API. Ensure you're using Chrome/Edge and grant folder access permissions.
4.
Verify Project Structure

Check the exported folder contains:

MyThreeJSScene/ ├── index.html (Main scene file) ├── scene.js (Three.js scene logic) ├── assets/ │ ├── models/ (OBJ files) │ │ └── object.obj │ └── textures/ (MatCap and other textures) │ ├── matcap_01.webp │ └── normal_map.jpg └── README.md (Usage instructions)
5.
Test Standalone Execution

Open index.html in a web browser and verify:

  • Scene renders correctly without the original application
  • All assets load properly (no 404 errors in console)
  • Interactions and animations work as expected
  • Project runs in different browsers (Chrome, Firefox, Safari)

Standalone Project Verification Checklist:

  • Complete project folder structure generated
  • All asset files copied to correct subdirectories
  • HTML file includes proper Three.js imports
  • JavaScript files are self-contained and executable
  • Asset paths use relative URLs for portability
  • Project works without internet connection (if local mode)
  • Cross-browser compatibility verified
  • No console errors on fresh load
  • Performance matches original application
  • README.md provides clear usage instructions

🐛 Troubleshooting Guide

Code Export Issues

  • Invalid JavaScript: Check for special characters in object names
  • Asset Path Errors: Verify texture/model file paths
  • Missing Imports: Confirm CDN vs local import settings
  • Animation Problems: Check animation state serialization

Standalone Project Issues

  • File Access Denied: Grant browser folder permissions
  • Missing Assets: Enable "Include Assets" option
  • Cross-Origin Errors: Use web server instead of file:// protocol
  • Large File Limits: Check browser download limits

🔍 Debug Tools
